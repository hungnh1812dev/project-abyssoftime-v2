# Entrypoint

Index of rule/doc files for this project. Any agent working on this repo only needs to start here.

- repo root `docs/workflow.md` — feature workflow (spec > build > update spec/docs > review > cleanup), module rules (max 500 lines, independent modules), commit, formatting, and naming conventions. Shared with the sibling apps.
- repo root `docs/rules/bun.md` — Bun runtime/tooling conventions (use Bun instead of Node.js, testing, frontend). Shared with the sibling apps.
- `/docs/documents/access-tokens.md` — Access Tokens module: entity/repository, create/list/delete/revoke services, secret hashing/rotation, the standalone unwired `ApiTokenGuard`, and the seed/permissions-repository cross-cutting edits it required.
- `/docs/documents/auth.md` — Auth module: register/verify-otp/login/refresh/logout/forgot-password/reset-password lifecycle, JWT cookies, the shared `common/` guards it depends on, why hashing uses `bcryptjs` instead of `Bun.password`, and email sending (`ConsoleEmailSender`/`SmtpEmailSender` via `@nestjs-modules/mailer`, Handlebars `.hbs` templates through `IEmailTemplateRenderer`), plus a practical env-setup guide (`EMAIL_PROVIDER` values, required vars, and where to get each vendor's API key) — see `auth-email-techstack.md`/`auth-email-providers-techstack.md` for the provider decision rationale.
- `/docs/documents/auth-issues-fix.md` — Auth module hardening: the 10 code-review findings (race condition on `super_admin` promotion, username/email duplication races, password/username validation, per-route rate limiting, trust proxy, timing side-channels, `ConsoleEmailSender`) and the issue/resolution/rationale/trade-off for each.
- `/docs/documents/token-blacklist.md` — Token Blacklist shared primitive (`src/common/token-blacklist/`, `@Global()` module): refresh tokens gain a `jti`, the two-port `ITokenBlacklistStore`/`ITokenBlacklistCache` split, Postgres-backed `PrismaTokenBlacklistStore` (authoritative), optional `RedisTokenBlacklistCache` (sticky-degraded on any Redis error, default-off via `REDIS_ENABLED`/`REDIS_URL`), `JwtRefreshStrategy`/`LogoutService`/`RefreshTokenService` wiring that makes logout and rotation actually revoke, known gaps (no expired-row sweep, pre-migration tokens unrevokable) — see `token-blacklist-techstack.md` for the decision rationale.
- `/docs/documents/content-type.md` — Content Type module: schema-as-code JSON definitions (`content-types/*.json`), `SchemaLoaderService`/`schema-validator`/`schema-differ`, the diff-based `ContentTypeSyncService` (never `DROP TABLE` on a field-level change), SQL identifier safety and Postgres 63-byte identifier hash-truncation (incl. `indexName()`); schema is read-only (JSON file + reboot), but `listFields` is admin-mutable via `PATCH .../list-fields` (`content_type:manager`, a separate `listFieldsOverride` column the sync engine never touches); no `document` import (module arrow is one-way).
- `/docs/documents/document.md` — Document module: draft/publish lifecycle (Mode A/B via `draftToPublish`), recursive component I/O (3-level nesting), single-type/collection-type/public REST surfaces (incl. the `/bulk`-route-ordering footgun), bulk create+publish/delete semantics, resolved `updatedBy` (`{ documentId, name } | null`) on every authenticated response — public routes untouched, `content-engine.e2e-spec.ts` against real Postgres; depends on `content-type.md`.
- `/docs/documents/graphql.md` — GraphQL module: `POST /graphql` (`@nestjs/graphql` schema-first + Apollo), SDL/resolvers generated dynamically at boot from `content-types/*.json` (no DB read, sidesteps the `OnApplicationBootstrap` sync-timing race), zero business logic — every resolver delegates to existing `document`/`content-type`/`media` services; `Authorization: Bearer <api-token>` auth reusing the unwired `ApiTokenGuard`'s verification logic; collection-type (query/list/CRUD/publish/unpublish, pluralized list query names, `documentId` args) + single-type (query/save/publish/unpublish, no `documentId`) schema generation; list queries return a `{ items, meta: { pagination } }` envelope with full `PaginationInput` (offset/page modes, `limit: -1` unlimited); `documentId`/`createdAt`/`updatedAt`/`publishedAt` system-field filters plus `and`/`or`/`not` combinators on every `<Type>Filter`; `createdAt`/`updatedAt`/`publishedAt` fields via a new `DateTime` scalar, `createdAt DESC` default sort; `formatError` whitelist, dev-only introspection gating; depends on `content-type.md`/`document.md`/`media.md`.
- `/docs/documents/media.md` — Media module: entity/repository, upload/list/delete services (size → dimension → storage → hash → persist ordering, uncaught storage-delete-before-DB-delete), `MediaController` (multipart via `memoryStorage()`, no `@types/multer`), `media:read`/`media:manager` guards, e2e infra (`bootTestApp`, `NoopStorageAdapter`); depends on `storage.md`.
- `/docs/documents/permissions.md` — Permissions module: entity, repository, DTOs, services, endpoints (guarded by `JwtAuthGuard`+`PermissionsGuard`), `countReferences`' real `accessTokenCount`, known quirks.
- `/docs/documents/roles.md` — Roles module: entity, repository (Prisma-backed, wired into `AppModule`), DTOs, services (default-role/permission-slug rules), full CRUD routes guarded by `JwtAuthGuard`+`PermissionsGuard` (the old `req.user.roleSlug` placeholder is gone).
- `/docs/documents/storage.md` — Storage module: `StorageAdapter` port, `S3StorageAdapter`/`CloudinaryStorageAdapter` implementations, `LazyStorageAdapter` (defers provider selection/config resolution to first call, `STORAGE_PROVIDER` defaults to `cloudinary`), no controllers — pure dependency consumed by `media.md`.
- `/docs/documents/users.md` — Users module: entity, repository, DTOs, services (level-hierarchy + super-admin-promotion rules on update/delete), endpoints, known gaps (no password hashing on this module's own routes, no roleId existence validation) — the admin-facing CRUD surface; see `auth.md` for the end-user register/login lifecycle.
- `/docs/documents/swagger.md` — Swagger/OpenAPI documentation: `@nestjs/swagger` bootstrap wiring (`GET /api-docs`, all environments), the `/api/v1` global prefix + unprefixed `GET /health` check, the cookie-auth-vs-bearer-auth reality check, full annotation coverage across all 10 controllers/19 DTOs, and the documentation-only response-shape DTOs added per module (no runtime behavior change).
- `/docs/documents/cors.md` — CORS: the single `app.enableCors()` delegate in `configure-app.ts` branching between a strict, credentialed, exact-match allowlist (`CORS_ORIGINS` env var) for `/api/v1/*` and an open, non-credentialed policy for `/api/v1/public/documents/*`, the `/health` fallthrough, and why (see `bootstrap-cors-techstack.md` for the decision rationale).
- `/docs/adding-a-content-type.md` — Practical how-to guide for adding a new content type: JSON file shape/field reference under `content-types/*.json`, what happens on boot/restart, the auto-generated REST routes, and what happens when you edit/rename/remove a content type later. See `/docs/documents/content-type.md` for the full internals.
- `/docs/cms-admin-integration.md` — Consumer-facing guide for building the CMS-Admin frontend against this API: hybrid cookie/Bearer auth model (refresh token in an httpOnly cookie, access token returned in the response body and sent as `Authorization: Bearer`), CORS-not-configured gotcha, error shape, permission-slug catalog, full per-module endpoint reference with request/response fields, collection-list pagination/filter query syntax, and known gaps (no user/media pagination, no locale support).
- `/docs/api-reference.md` — Flat per-endpoint lookup (every route across all modules) in strict Endpoint/Request/Response/Error format, for quick reference while wiring up CMS-Admin — no prose/gotchas (see `cms-admin-integration.md` for those).
